# Event System

The event system is a **static typed bus** built around three components: an `Event` struct that carries a bitmask category flag, an `EventSystem` abstract base class that each subscribing system implements, and the `EventManager` static dispatcher that routes pushed events to all registered listeners.

## Overview

| Component | Type | Responsibility |
|---|---|---|
| `EventsCategory` | `enum` (bitmask) | Identifies the channel a given event belongs to |
| `Event` | Base `struct` | Payload carrier — stores a `u32` category bitmask |
| `EventSystem` | Abstract base class | Receives events into a circular queue; subclasses define processing |
| `EventManager` | Static utility class | Maintains the subscription map; dispatches events to listeners |

Dispatch is **synchronous on the calling thread**. `EventManager::PushEvent()` immediately calls `ReceiveEvent()` on every registered `EventSystem` for that category, which enqueues the event into the system's circular buffer. Each system then drains its queue the next time `ProcessEvents()` is called — typically once per frame.

## Event Categories

**Header:** `Falcon/Core/Events/Event.h`

Categories are bitmask values generated by the `BIT(x)` macro (`1 << x`). A single `Event` can carry multiple categories via `SetFlag()`.

| Category | Bit | Value | Subscribers |
|---|---|---|---|
| `none` | — | 0 | — |
| `EVENT_WINDOWS` | 0 | 1 | Window management |
| `EVENT_KEY_INPUT` | 1 | 2 | `CarEventSystem` |
| `EVENT_MOUSE_INPUT` | 2 | 4 | `CarEventSystem` |
| `EVENT_RENDER` | 3 | 8 | `RenderEventSystem` |
| `EVENT_PARTICLE` | 4 | 16 | `ParticleEventSystem` |
| `EVENT_DATA_TO_RENDERER` | 5 | 32 | `RenderEventSystem` |
| `EVENT_CAMERA_COMPONENT` | 6 | 64 | — |
| `EVENT_CAR_CREATED` | 7 | 128 | `CarEventSystem` |
| `EVENT_CAR_AI_INPUT` | 8 | 256 | `CarEventSystem` |

## Event Struct

**Header:** `Falcon/Core/Events/Event.h`

`Event` is the base payload type for every dispatched event. Concrete event types subclass it and add their own data fields.

| Member / Method | Description |
|---|---|
| `u32 m_eventFlag` | Bitmask of all categories this event belongs to |
| `Event(EventsCategory category)` | Constructor — initialises `m_eventFlag` with the given category |
| `SetFlag(category)` | ORs `category` into `m_eventFlag` — adds a second category to an existing event |
| `GetFlag()` | Returns the raw `u32` bitmask |
| `CheckCategory(referenceType)` | Returns `true` if the event's flag has `referenceType` set (bitwise AND test) |

All event instances are passed as `boost::shared_ptr<Event>` throughout the system.

## EventSystem Base Class

**Header:** `Falcon/Core/Events/EventSystem.h`

`EventSystem` is an abstract base class. Every subsystem that wants to receive events subclasses it, populates `subscribedList` with the desired categories, calls `SubscribeToEvents()` in its constructor, and implements `ProcessEvents()` to drain its queue each frame.

**Protected members:**

| Member | Type | Description |
|---|---|---|
| `eventQueue` | `boost::circular_buffer<boost::shared_ptr<Event>>` | Fixed-capacity queue (100 events); wraps on overflow |
| `subscribedList` | `boost::container::vector<EventsCategory>` | Categories this system registered for, populated in the subclass constructor |
| `m_threadPool` | `ThreadPool*` | Shared reference to the engine `ThreadPool`; available for job submission inside `ProcessEvents()` |

**Public interface:**

| Method | Description |
|---|---|
| `SubscribeToEvents()` | Pure virtual — implemented by each subclass to call `EventManager::SubscribeToEvent(this, category)` for each entry in `subscribedList` |
| `ProcessEvents()` | Pure virtual — implemented by each subclass to drain `eventQueue` and act on each event |
| `ReceiveEvent(event)` | Concrete — pushes the incoming `boost::shared_ptr<Event>` onto `eventQueue`; called by `EventManager::PushEvent()` |

The `eventQueue` circular buffer has a fixed capacity of **100 events**. If the queue is full when `ReceiveEvent()` is called the oldest entry is overwritten.

## EventManager

**Header:** `Falcon/Core/Events/EventManager.h`

`EventManager` holds one static subscription map and exposes two static methods. No instance management is required.

**Static data:**

| Member | Type | Description |
|---|---|---|
| `systems` | `boost::unordered_map<EventsCategory, std::vector<EventSystem*>>` | Maps each category to the list of systems registered for it |

**Static methods:**

| Method | Parameters | Returns | Description |
|---|---|---|---|
| `SubscribeToEvent` | `EventSystem* sys, EventsCategory category` | `void` | Registers `sys` in the `systems` map under `category`; creates the bucket if it does not yet exist |
| `PushEvent` | `boost::shared_ptr<Event> event, EventsCategory category` | `bool` | Calls `ReceiveEvent(event)` on every `EventSystem*` in `systems[category]`; returns `true` if at least one system was notified |

`PushEvent` returns `false` silently if no system has subscribed to the category — undelivered events are dropped without error.

## Concrete EventSystems

### RenderEventSystem

**Header:** `Falcon/Rendering/PipeLine/Renderer.h`

Singleton (`GetInstance()`); friend of `Renderer`.

| Subscribed category | Purpose |
|---|---|
| `EVENT_RENDER` | Mesh / material submission from the scene |
| `EVENT_DATA_TO_RENDERER` | Sky and terrain mesh delivery from `SceneGraph` |

Holds `Mesh* m_skyMesh` and `Mesh* m_terrainMesh` populated when the `SceneGraph` constructor pushes an `EVENT_DATA_TO_RENDERER` event. `Renderer` reads these via `GetSkyMesh()` and `GetTerrainMesh()` each frame.

| Method | Description |
|---|---|
| `GetInstance()` | Returns the singleton pointer, allocating on first call |
| `GetSkyMesh()` | Returns `Mesh*` for the sky dome |
| `GetTerrainMesh()` | Returns `Mesh*` for the terrain |
| `ShutDown()` | Static — releases the singleton |
| `SubscribeToEvents()` | Registers for `EVENT_RENDER` and `EVENT_DATA_TO_RENDERER` |
| `ProcessEvents()` | Drains the queue each frame; routes mesh/material data to the `Renderer` pipeline |

### ParticleEventSystem

**Header:** `Falcon/Rendering/ParticleSystem.h`

Singleton (`GetInstance()`).

| Subscribed category | Purpose |
|---|---|
| `EVENT_PARTICLE` | Particle emitter spawn / update commands |

`ProcessEvents()` is called by `ParticleSystem::Update()` each frame to consume spawn requests queued from gameplay code.

| Method | Description |
|---|---|
| `GetInstance()` | Returns the singleton pointer, allocating on first call |
| `SubscribeToEvents()` | Registers for `EVENT_PARTICLE` |
| `ProcessEvents()` | Drains the queue and forwards emitter data to `ParticleSystem` |

### CarEventSystem

**Header:** `Falcon/Physics/CarSystem.h`

Owned by `CarSystem`; friend of `CarSystem`.

| Subscribed category | Purpose |
|---|---|
| `EVENT_CAR_CREATED` | Registers a newly constructed vehicle with `CarSystem` |
| `EVENT_KEY_INPUT` | Keyboard drive mode delivery to the user car |
| `EVENT_MOUSE_INPUT` | Mouse input delivery to the user car |
| `EVENT_CAR_AI_INPUT` | AI drive mode delivery to AI cars |

`ProcessEvents()` is called by `CarSystem::Update()` each frame. `EVENT_CAR_CREATED` processing calls `CarSystem::AddCar()` to add the car to the appropriate array.

| Method | Description |
|---|---|
| `SubscribeToEvents()` | Registers for all four categories listed above |
| `ProcessEvents()` | Routes each event type to the appropriate `CarSystem` handler |

## Publish / Subscribe Pattern

The full lifecycle for one event:

| Step | Call | Notes |
|---|---|---|
| 1 — Subscribe | `EventSystem::SubscribeToEvents()` | Called in each subclass constructor; registers `this` with `EventManager` for each category in `subscribedList` |
| 2 — Construct | `boost::make_shared<ConcreteEvent>(...)` | Caller creates a heap-allocated event via a `boost::shared_ptr` |
| 3 — Publish | `EventManager::PushEvent(event, category)` | Iterates `systems[category]`; calls `ReceiveEvent(event)` on each registered listener |
| 4 — Queue | `EventSystem::ReceiveEvent(event)` | Pushes the shared pointer into the listener's `eventQueue` circular buffer |
| 5 — Process | `EventSystem::ProcessEvents()` | Drains `eventQueue`; called once per frame by the owning subsystem |

An event can be published to multiple categories in one call by issuing `PushEvent` once per category, or by setting multiple bits via `Event::SetFlag()` before dispatching.
